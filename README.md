# 债券询价数据整理工具（两个 Windows 桌面工具）

面向债券发行/销售场景的数据整理工具。把每天手工做的两件事自动化：
**① 把各家机构发来的询价反馈整理成标准明细表**；**② 把同一批债券两个品种（如 3+2 年 / 5 年）的两份导出表合并成一张。**

纯 Python + tkinter 自绘 GUI，打包为单文件 exe，双击即用，不需要装 Python、不需要联网、不上传任何数据。

---

## 一、解决的问题

债券询价的工作节奏是：向几十上百家机构（银行、理财、资管、专户、投顾…）逐个询量，回收的反馈是**格式不一、口径不一、还带大量口语化描述**的表格。每天要把它们：

- 按"能不能参与、参与意愿强弱"分类；
- 按业务种类、机构类型排序；
- 把新的反馈并进昨天的进度里，保留历史；
- 生成一份可直接对外发的标准明细表（含合计、小结、条件格式）。

手工做一遍 30–60 分钟，且容易在"同一个机构多个产品"、"备注里写了金额但写得很口语"这类地方出错。第二个工具解决的是另一件事：同一批债两个品种分别导出后，需要按机构 + 业务种类对齐合并，人工核对两份表的进度措辞是否一致、金额取哪个，非常耗时。

## 二、工具一：债券询价明细表处理工具

**输入**：一份询价导出表（.xls / .xlsx，允许前面有标题行、允许列名不完全一致）
**输出**：`输出询价明细表（）-YYYYMMDD.xlsx`，与输入同目录

### 处理链路

1. **表头自动定位**：前 40 行逐行打分（列名别名命中 ×2 + 非空单元格数），取最高分行为表头。解决"导出表第一行是合并标题、第二行才是表头"的问题。
2. **列名别名映射**：每类字段维护一组别名。"意向投标量（亿元）"这一字段就收了 17 种写法，包括客户表里写"意向投标量（万元）"的情况——只做字段识别，不擅自改数值单位。
3. **分类判定**（两级四类）：
   - 先判"能不能参与"：审批进度 = 项目未通过 → 无法参与；
   - 再按机构类型区分银行 / 非银（机构类型或名称含 银行、农商、农信、信用社、村镇银行、农合 → 银行）；
   - 结果四类：有概率参与的银行 / 有概率参与的非银 / 无法参与的银行 / 无法参与的非银。
4. **话术分级（关键词规则引擎）**：把询价进度回填的自由文本映射成有限档位。
   - 有概率参与 7 档：认购意向高 → 当天报量 → 推介中 → 观望中 → 认购意向低 → 在库待沟通 → 认购意向不明（兜底）；
   - 无法参与 8 档：不参与 → 价格原因 → 资质不符 → 额度受限 → 不在库 → 其他 → 流程/时间受限 → 利率原因；
   - 判定按优先级顺序短路，先命中先归类；金额/比例出现明确数值或"参与/会参与"这类明确表态，直接判为高意向。
5. **认购意向评分**（只对"有概率参与"打）：高意向 / 当天报量 = 1，低意向 = −1，其余 0，无法参与留空。原始文本同时含"有意向"和"兴趣不大"这类混合信号时，靠二次检查取更保守的结论。
6. **六键稳定排序**（mergesort，保证同键顺序不抖动）：
   分类（固定四类序）→ 话术档位 → 更新时间（新在前）→ 金额（高在前）→ 业务种类（自营→资管→理财→专户→投顾→公募）→ 机构名（升序）。
7. **进度回填与富文本**：把当天的新反馈以 `【MMDD】` 标签 + 话术的形式写进"询价进度"列，历史写在前面；导出时**日期不加粗、话术加粗**，一列里能一眼扫出"今天发生了什么、机构什么态度"。
8. **报表输出**：读模板的标题（A1）、债券信息（B2）、表头行（第 3 行）等参数，但**不是复制模板文件**，而是按参数重建整张表——所以模板改动不会把旧格式带进结果。含：分类底色（四类四种主题色）、分类列合并、分组合计行、8 行小结区（浅绿）、认购意向列三色交通灯条件格式（1 绿 / 0 黄 / −1 红）、按内容长度估算行高、全表框线。
9. **附"整理数据"sheet**：把参与排序和统计的六列原始值再列一遍，方便复核"这个结论是怎么来的"。

## 三、工具二：债券询价双表合并工具

**输入**：品种一、品种二两份询价导出表（各拖一个到对应区域）
**输出**：合并后的明细表，备注列标注每行来自哪个品种

### 处理链路

1. **匹配键** = （机构名称, 业务种类）。同一机构的不同产品是不同行，不会被错误合并。
2. **进度一致性判定**（决定"合成一行"还是"并列两行"）：先做保守的规范化（只替换"没有→无"这类高置信度同义，去掉结尾标点），再依次尝试：规范化后完全相等 → 去掉 `【MMDD】` 标签后相等 → 包含关系。**不做模糊匹配**——宁可并列两行让人看，也不把两个不同的态度合成一句。
3. **合并策略**：
   - 进度一致 → 一行，备注"品种一 / 品种二"；
   - 进度不一致 → 两行相邻排列，机构/业务/备注单元格黄色高亮，一眼看出"这家在两个品种上态度不同"；
   - 金额取较大值、评分取较高的那个、进度文本保留信息量更长的一条（相似时）；
   - 意向不同时，两行文本并列展示（品种一在上、品种二在下）。
4. **排序**：以"机构 + 业务种类"为一个组，组间按组内最好的话术档位、最新时间、最优金额排序，组内相邻——保证同一家机构的两个品种不会被拆散到表的两处。
5. **输出**：七列（多一列"备注"），品种来源用浅色底标注，合并行用黄色标注，合计行只加在"有概率参与"分类末尾，小结区口径与工具一一致但按（机构, 业务种类）去重计数。

## 四、技术栈与实现要点

- **语言 / 库**：Python 3.10+，pandas 读表与清洗、openpyxl 生成带样式与条件格式的 xlsx、xlrd 兼容老的 .xls。
- **GUI**：tkinter（标准库）+ ctypes 直接调 Win32 API 实现文件拖拽（`WS_EX_ACCEPTFILES` + `WM_DROPFILES` + `DragQueryFileW`）；后台线程跑处理、`root.after(0, ...)` 回主线程更新界面，处理大表时窗口不假死；`sys._MEIPASS` 适配 PyInstaller 单文件解包路径。
- **打包**：PyInstaller `--onefile --windowed`，产物 32 MB 左右，双击运行，无控制台窗口。
- **工程取舍**：
  - 规则用"关键词 + 优先级短路"而不是模型，因为业务方需要**能解释、能改、结果稳定**——同一份输入必须每次输出一样；
  - 列名别名表独立维护，新出现的客户表写法加一行就能支持，不用改主流程；
  - 不复制模板、按参数重建报表，避免模板被历史格式污染。

## 七、说明

工具在真实业务数据上迭代了多轮（列名差异、口语化反馈、多产品机构、跨天进度拼接），规则表是跟着真实样本一条条补出来的；代码里没有硬编码任何机构名或业务数据。
